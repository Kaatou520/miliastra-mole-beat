## 目标
把网页原型 `web/index.html` 的打地鼠场景 **1:1** 搬进千星（2D + 客户端 Lua）。
先把这一个场景做完，商店 / 转盘 / 老虎机之后再说。

Lua 侧：`parts[]` + 每帧 `stepParts(dt)`。命中时 `impactAt()` 按网页参数随机生成
（普通 11~15 块、岩属性 16~20 块，冲击环 1~2 圈，四角星 2~4 颗），
逐帧算位置/缩放/旋转/透明度，寿命到点用 `game.DestroyClientUIControl` 销毁。
透明度量化到 6 档（`aByte`），避免每帧重建图元。
BONUS：彩虹环实例 +「BONUS!」涂鸦字常驻（缩放 1.75 = 70px）+ 倒计时文本 + 每次命中飘 `+N`；
爆炸时大史莱姆放大到 3.2 倍并淡出，0.42 秒后收尾；BONUS 期间隐藏 9 个判定区，只让「判定大」吃点击。

**推镜（camZoom）**：千星没有相机，直接缩放挂载控件 n1（全屏 stretch 容器）就等价于
网页 `applyCam()` 给 `.screen` 加 `scale`——场景树是父子嵌套，子控件跟着父级矩阵一起放大，
点击也会经父矩阵逆变换，所以不会错位。
- 每次命中大史莱姆 `camZoom = min(0.52, camZoom + 0.05)`
- 停手超过 0.36 秒后按 `camZoom *= e^(-2.76·dt)`（≈ 网页 0.955/帧 @60fps）回落
- 命中抖 ±6px / 0.18 秒，爆炸 ±11px / 0.3 秒（写 n1 的 `anchoredPosition`）
- 网页 `.screen.bonus` 会淡出 HUD，这里用 `hudSet(false/true)` 一起隐藏 28 个 HUD 控件
- 已知取舍：n1 在浏览器试玩里是 Pixi render group，放大 1.5 倍是纹理重采样，会轻微发糊；
  要完全锐利得改成逐个控件缩放（写 4 个字段/控件/帧），首版先保持整树缩放

验证：`mobile-16-9` 与 `pc-16-9` 均对位；单击命中约 24 个实例、1.2 秒后归零；
BONUS 超时与爆炸两种收尾都会恢复判定区 / 提示行 / 倒计时 / 大史莱姆状态；
连打时 n1 缩放 1.0 → 1.52（7 下实测 1.35），停手 1 秒回到 ~1.04、3 秒回到 1.00，HUD 同步隐藏/恢复。

## 商店 / 转盘 / 老虎机（本轮已完成）
三个全屏容器页面 `商店页` / `转盘页` / `老虎机页`（默认 visible=false），入口是左上三张卡片上的
`商店-入口` / `转盘-入口` / `老虎机-入口` 光标区；打开任一页面时 OnUpdate 在 `if page then return end`
处停住出地鼠，返回后恢复。页面内控件都在容器里，Lua 取不到 `root:GetChild`，统一走 `cachePage()` 缓存

## 新手引导（本轮）
开局 `S.coins = 1`，三步引导，提示文字直接复用 `fx涂鸦` 模板的**常驻实例**
（`spawnWord(..., keep=true)`：白字 + 靛蓝描边 + 粉/青错位，和打地鼠命中字完全同一套）：

## 画布适配（本轮修复）
之前 PC 用 `baseScale = min(w/1280, h/720)` 缩放挂载控件，16:9 刚好铺满；但手机画布不是 16:9
（19.5:9 / 4:3）时，1280×720 的内容会居中留出黑边，HUD 也缩在中间 —— 这就是「手机端没覆盖全屏」。

修法分三层：
1. **背景铺满**：`bg-天空` 改成 2600×1600、`bg-地面` 2600×800（顶边仍在设计 y=380）、
   `bg-地砖线`/`bg-栏杆`/`bg-栏杆上边` 加宽到 2600 —— 任何画布都不会露出底色。
2. **页面铺满**：`商店页`/`转盘页`/`老虎机页` 容器改成 stretch 锚点（box = 画布），
   背板 `商店-遮罩`/`转盘-底`/`老虎机-底` 与 `转盘-闪光`/`老虎机-闪光` 也 stretch；
   打开页面时 `page:SetAsLastSibling()`，避免运行时的云实例压住页面。
3. **HUD 贴边**：OnStart 里按 `GetUICanvasSize()` 算四边余量 `L/R/T/B`，把左侧卡片列、金币/武器、
   右上提示气泡、右下音效/重开、顶部进度条与连击、三个入口光标按余量位移；
   16:9 画布位移为 0（PC 1.25 缩放不受影响），19.5:9 左边距 -140，4:3 顶/底 ±120。
   引导提示：第一步用 `hintNearCard()`（读「转盘-入口」的实际偏移，贴在卡片右侧），
   关卡内底部提示用 `hintScreen()` 按屏幕坐标摆。

**踩到的坑**：
- Lua 主 chunk 的局部变量上限是 200 个（`too many local variables`）——本轮把 `FIT_*`、字色、
  转盘/老虎机常量合并成表才压下来，后续加顶层 local 要注意。
- `转盘-中奖格` 是扇区容器的子节点，`cachePage` 只取页面直接子节点，需单独 `W['转盘扇区']:GetChild(...)`。
- 背景云是运行时实例（在 root 子列表最前），会压住页面，打开页面时要 `SetAsLastSibling()`。

验证：19.5:9（1560×720）、4:3（1280×960）、PC（1600×900）三档截图均为整屏铺满、无黑边、HUD 贴边；
背景云不再盖住转盘/商店页；无 Lua 错误。


## 关键技术约束（都踩过）
1. `load`/`patch` 会回传**整份快照**（单次 60 万字节）→ 一回合只调一次，控件树改动攒批；
   Lua 改动走 `updateScript` 小补丁，或写文件让用户从顶栏「工作区存档」载入。
   也可以直接 POST 本地 `/qxqy-simulator/api/{load-archive,patch,play}`（见 `_scratch/reload.cjs`），
   响应自己解析，不占模型上下文
2. 图元 id：`100001 rect / 100002 circle / 100003 triangle / 100004 四角星 / 100005 五角星 / 100006 ring`
3. 图片只能走白名单；元件用 Prefab 来源（水 30002006 / 冰 30002001 / 岩 30002008 / 爆桶 20001599 / 金币 10005009 / 宝箱 10005008、10005006 / 摊位 20001125 / 风车 10005010）
4. 编辑器同级列表**第一项在最上** → children 数组要反着写（运行时实例默认插到最前 = 最上层）
5. 文本框高度 < 字号 × 1.75 会把文字裁掉
6. 运行时 `anchoredPositionX/Y` **可以写**，但它是「相对父容器中心」的偏移：
   `offsetX = 屏幕x − 640`、`offsetY = 360 − 屏幕y`（画布 1280×720，y 向下）。
   早先直接写屏幕坐标才会跑到右上角 —— 不是 API 不生效
7. 史莱姆图片压在判定区上面会吃掉点击 → 图片默认 `raycastTarget=false`，判定区才是 `cursor`
8. `OnStart` 里必须 `script:EnableUpdate(true)`，否则 `OnUpdate` 根本不跑（史莱姆一只都不生成）
9. `until` 是 Lua 保留字（`h.until` 直接编译失败）
10. 画布用 `mobile-16-9`（1280×720）；PC 上整套内容按 1280×720 居中留边，特效仍对位
